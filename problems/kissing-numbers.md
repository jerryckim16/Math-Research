## Statement

The kissing number $\tau_{n}$ is the largest number of non-overlapping unit balls in $\mathbb{R}^{n}$ that touch a central unit ball. Equivalently, it is the largest $N$ for which there are nonzero vectors $x_{1},\dots,x_{N} \in \mathbb{R}^{n}$ with pairwise angles $\ge 60^{\circ}$, i.e. $\langle x_{i},x_{j}\rangle \le \tfrac{1}{2}\lvert x_{i}\rvert\lvert x_{j}\rvert$ for $i \ne j$.

**Exact criterion used here.** For integer vectors $a$, $b$, put $p = a\cdot b$, $A = \lvert a\rvert^{2}$, $B = \lvert b\rvert^{2}$. The angle is $\ge 60^{\circ}$ iff

$$p \le 0 \quad\text{or}\quad 4p^{2} \le AB,$$

which for integer $p$ means $p \le T(A,B) := \operatorname{isqrt}(\lfloor AB/4\rfloor)$. A repeated point (or a positive multiple) has $4p^{2} = 4AB > AB$, so passing the check also certifies that the $N$ directions are distinct. A configuration of integer rows that passes the check for every pair, and whose rows lie in an $n$-dimensional subspace, proves $\tau_{n} \ge N$.

## Approaches

### 1. Exact pairwise check of complete configurations (worked)

- **Idea:** check the criterion above for every pair, in exact integer arithmetic, with two independent implementations. Validate on known configurations and on deliberately broken ones first.
- **Implementation** (`computations/kissing/`):
  - `kiss_check.c` (C, OpenMP). Rows are int8; dot products are accumulated in int16. This is exact because every squared norm is $\le 32767$: by Cauchy–Schwarz, each partial sum is at most $\sum\lvert a_{k} b_{k}\rvert \le \lvert a\rvert\lvert b\rvert \le \max(A,B)$. The program checks this precondition. It reports violations, the maximum excess $p - T$, the number of exact $60^{\circ}$ contacts, and the largest $p$ per pair of norm classes.
  - `kiss_check_np.py` (numpy, float32 GEMM). It is exact because every partial sum is an integer of absolute value $< 2^{24}$ (same Cauchy–Schwarz bound), and any flagged pair is recomputed in int64.
  - `check_mixed.py` handles the 38D int64 exports. Pairs of small rows go to `kiss_check.c` (written out as int8). Huge-row $\times$ small-row pairs are computed exactly by splitting each entry as $\mathrm{hi}\cdot 2^{31} + \mathrm{lo}$ in int64, then recombining in Python integers wherever a float64 screen (margin $10^{-6}$ in cosine) cannot decide. Huge $\times$ huge pairs use exact Python-integer dot products. It also checks the dimension: columns 38–51 equal columns 24–37 in every row, so the rows span $\le 38$ dimensions, and the rank modulo $2^{61}-1$ of a 3,205-row sample is 38.
  - `build_lin.py` rebuilds Lin's configurations from his certificate files with our own parser. It assumes nothing about their validity and only checks the claimed counts.
    For 38D the base (Kravatskiy's 591,612 points) is taken from the Qiushi export, not rebuilt from the base data Lin ships. The check of the assembled set is unconditional: it proves $\tau_{38} \ge 605{,}322$. That this set is exactly Lin's construction rests on two things. First, Lin's seven `certificates/d38/base-data/` files are byte-identical (sha256) to `constructions/d38/base-data/` in the Qiushi repository; we checked this. Second, the Qiushi export is built from that data; we did not re-derive it.
- **Validation:**
  - $D_{4}$ (24, 96 contacts), $D_{5}$ (40, 240 contacts), $E_{8}$ (240, $6720 = 240\cdot 56/2$ contacts) and the Leech minimal vectors (196,560, $452{,}088{,}000 = 196560\cdot 4600/2$ contacts; built from our own Golay code, whose weight enumerator is checked) all pass in both implementations, with exactly the classical contact numbers.
  - Negative controls fail: an added short vector, one perturbed coordinate in $E_{8}$, a duplicated row, and a scaled copy of a row.
  - On 50 random integer sets with mixed norms (40 failing, 10 passing), C, numpy and a pure-Python big-integer reference agree exactly on violation and contact counts.
  - check_mixed: $E_{8}$ with five rows rescaled by $10^{15}+37$ passes, and adding a rescaled copy of an existing row fails.
  - On real data, Qiushi's 32D file with row 0 duplicated, or replaced by the sum of itself and a $60^{\circ}$ neighbour, must fail (`perturb.py`).
- **Outcome:** see §Results.

### 2. Qiushi 25D and 27D: rebuild from repository data, exact check over $\mathbb{Q}(\sqrt{2}, \sqrt{3})$ (worked)

- **Rebuild** (`build_qiushi2527.py`, our own code). It follows the paper's construction text and reads only the six pinned data files; none of the authors' code is run. The Leech shell is our own (`known.py`, the same Golay generator polynomial as the authors'; a coordinate-convention mismatch would show up as owners missing from the shell). The builder re-derives and asserts the structural facts the counts depend on.
  - 25D: all 1,016 head owners lie in our shell and are distinct. The layer $\{w : w\cdot g = 24\}$ has exactly 552 points, and it equals $\{u + g : u\cdot g = -24\}$, whose members $u$ are all owners.
  - 27D: each first-layer head has at most one shell vector with $y\cdot z > 48$, giving 2,090 distinct owners. The 311 second-layer owners lie in the shell and are disjoint from the 2,090.
  - The point counts come out as 197,580 and 201,567, equal to the claims.
- **Coordinates are not integral.** 25D needs $\sqrt{2}$, $\sqrt{3}$, $\sqrt{6}$ (the moved block and $Q$'s plane) and 44 rational heads with denominators up to about $3.5\cdot 10^{18}$. 27D needs $\sqrt{2}$ and $\sqrt{3}$. Each point is therefore stored, up to a positive factor (which does not change angles), as $x = C_{0} + C_{1}\sqrt{2} + C_{2}\sqrt{3} + C_{3}\sqrt{6}$ with integer vectors $C_{k}$. The configuration splits into two parts:
  - a pure-integer "bulk" (int8, norm $\le 32767$): 25D has 194,992 unmoved shell rows plus $P_{0} \propto (-g, 0)$, the poles, $Q \propto (g, -4)$ and $R_{-} \propto \ell$, 194,997 rows in all; 27D has the 194,159 remaining shell rows;
  - "field" rows: 2,583 in 25D and 7,408 in 27D.
- **Checks.**
  - Bulk $\times$ bulk pairs go through the existing `kiss_check.c` and `kiss_check_np.py`.
  - Every pair involving a field row goes through the new `kiss_check_field.py`. It computes every squared norm exactly and requires it to be a positive integer. It has two independent decision modes:
    - *float*: a float64 cosine screen with margin $10^{-9}$, with a rigorous rounding bound below $10^{-11}$ (conditioning checked per row). Undecided pairs get an exact sign of $a + b\sqrt{2} + c\sqrt{3} + d\sqrt{6}$ by repeated squaring in Python integers.

- **Validation** (`test_kissing.py` §5).
  - $E_{8}$ with rows multiplied by $\sqrt{2}$, $\sqrt{3}$, $\sqrt{6}$ or $7\cdot 10^{18}+1$ passes with 6720 contacts in total.
  - The 12 rotated cuboctahedron tails of the 27D construction pass with 24 contacts.
  - Bad rows are caught.
  - Both modes agree with a pure-Python exact reference.

### 4. Dims 11 and 12: the 604- and 841-point records (worked)

- **11D, $\tau_{11} \ge 604$ (EinsteinArena, arXiv:2606.10402v2).** `build_einstein11.py` builds the configuration from the appendix text alone (the hosts with the authors' coordinates are refused here). The backbone has 496 points: $\pm 2e_{i}$ ($i < 8$) and all signs on 30 four-point supports. There are 96 points $\pm e_{a} \pm e_{b} \pm \sqrt{2} u_{j}$ for the pairs $(a,b) \in \{(0,6), (1,4), (2,5), (3,7)\}$, and 12 points $\sqrt{2}(\pm u_{i} \pm u_{j})$, where $u_{1}$, $u_{2}$, $u_{3} = (2,1,2)/3$, $(2,-2,-1)/3$, $(1,2,-2)/3$ sit in coordinates 8–10.
  - The appendix does not say which 8 of the 32 "transversal" triples make up each of the three layers. The kissing condition forces two things: triples in the same layer meet in at most one element, and no triple appears in two layers. The builder takes the lexicographically first valid choice (printed in its output). With it, the full configuration passes, so the bound holds for this completion of the appendix's construction.
  - Scaled by 3, the backbone is integral and the other 108 points lie in $\mathbb{Z}[\sqrt{2}]^{11}$. `kiss_check.c` checks backbone $\times$ backbone, and `kiss_check_field.py` (both modes) checks everything else.
  - The contact count is $17{,}088 + 2{,}616 =$ **19,704**. This equals the count the Station paper (arXiv:2608.23691v2, §S1) gives for its Construction 1, which it identifies with EinsteinArena's. Our backbone alone has 17,088 contacts, the size of the "active set" the EinsteinArena paper reports for the basin of its first valid (594-point) solution; the paper says that the backbone is shared by its 594–600 constructions. So our completion appears to be the published configuration up to isometry (the contact count is an isometry invariant; this is evidence, not proof, of isometry).
  - Negative controls: `--variant repeat` (layer 9 reuses a triple of layer 8) fails with 96 violations, and `--variant pairmix` (8 extra points $\pm e_{0} \pm e_{1} \pm \sqrt{2}u_{1}$ on the non-pair (0,1)) fails with 80 violations.
- **12D, $\tau_{12} \ge 841$ (Takhanov–Assylbekov–Yun, arXiv:2606.18984v2).** The configuration was found by numerical optimisation, and the paper gives only a floating-point maximum inner product. `check_decimal.py` reads every decimal literal of the published `gram841_coordinates.txt` **exactly** as a rational number, scales each row to integers (the rows are not exactly unit vectors, which does not matter because angles are scale-free) and decides $4p^{2} \le AB$ in Python integers for all 353,220 pairs. So the published 841 points themselves, taken as exact rationals, form a kissing configuration.
  - Largest cosine 0.499999937751432 (pair 413, 756); exact $1/4 - \cos^{2} = 6.22\cdot 10^{-8}$. There are no contacts.
  - Negative controls: duplicating a row (1 violation), appending row 413 + row 756 (45 violations), and moving row 413 towards row 756 by $10^{-6}$ (8 violations; cosine 0.5000037) all fail. The last shows that the check resolves the $6\cdot 10^{-8}$ margin.
  - Kravatskiy's repository also contains an audit of this file (`research/dim12_paper_audit_20261104/decimal841_certificate.json`). We did not read it, so ours is not the only exact check of this file.
